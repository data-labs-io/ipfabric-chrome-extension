Sent as Authorization: Bearer … to your endpoint. Stored in chrome.storage.sync. Required for hosted services (OpenAI, Groq, Azure); leave blank for local servers (Ollama, LM Studio, LocalAI, vLLM) that don't require a key.
Your Anthropic API key. Stored in chrome.storage.sync (synced to your Google account) and sent only to api.anthropic.com. Treat it like a password — anyone with access to your browser profile can read it. Manage keys at console.anthropic.com.
Seeing a 401 “CORS requests are not allowed for this Organization”? That is an Anthropic organization setting, not an extension bug. The extension already strips the browser Origin header from its Anthropic requests to avoid CORS mode, but if your org explicitly disables CORS the call is still blocked. Fix it in the Anthropic Console → organization Settings → enable Allow CORS requests (or use a key from an org that permits them).

The extension speaks MCP's Streamable HTTP transport directly from the background service worker — it does not spawn npx mcp-remote. On first use it runs initialize, sends notifications/initialized, then tools/list to find a global-search tool, and finally tools/call with your query.
